# 本次验证记录

日期：2026-11-09 至 2026-11-11（北京时间）。运行环境：Linux x86_64，Python 3.11.17，PyBullet 3.2.7，CPU TinyRenderer。依赖精确版本见 `requirements-lock.txt`。

机器人模型为 **myCobot 630 Pro**（`configs/default.json`，官方 Pro630 URDF，臂展约 630 mm）。工位按该臂展布置：底座位于 Base 原点、底座高 0.16 m，托盘 200 × 324 × 12 mm 架在挂于左右侧壁的钢丝层架上（层架 204 × 328 mm，托盘四边各比层架内缩 2 mm），Food ROI 180 × 120 × 60 mm。烤箱腔体为 X=[240,620]、Y=[−176,176] mm，底板顶面 Z=−30 mm，侧壁与 +X 前侧挡板厚 12 mm、顶面 Z=160 mm，−X 面与顶面敞开。XY 采样 X=[330,470]、Y=[-70,70] mm。

采样配置为**单层基准高度 200 mm + Z 扰动 Δ=0.02 m + N=8**：每个候选在该高度上独立抽 δ ~ U(−0.02, +0.02)，实际光心 Z 落在 0.200–0.240 m。场景结构为「腔体底板 →（无接触）→ 挂壁钢丝层架 → 托盘 → 食材」：层架不是落地支架，而是两条外侧钢条贴在左右侧壁内表面、横档贯通腔内全宽，因此由侧壁承载；层架顶面取托盘底面，食材坐在托盘上表面（= `roi.tray_z_B_m` = 20 mm），层架下沿离腔底 35 mm。前侧挡板宽度等于腔体外宽并与左右侧壁在角部重叠，因此四面闭合、无缝隙；`tests/test_scene.py` 从腔体内部向 +X、±Y、−Z 方向做射线扫描，任何位置漏出都会失败，同时断言层架两端贴墙、上下只有一层钢丝厚度（即无支腿）、托盘铺满层架且不超出层架。

## 基准高度与图像边距的选择依据

相机高度受「完整入镜」约束限制：Food ROI 的 8 个顶点必须在图像边距内全部可见。在较早的紧凑工位（托盘距底座 0.18 m）上做过一组纯几何实测（每层 15 个采样点）：

| 高度 | 几何通过 | 说明 |
|---|---:|---|
| 140–180 mm | 0/15 | 全部 `food_out_of_rgb_fov` |
| 200 mm | 2/15（边距 10%）→ 15/15（边距 5%）| 边距是本层的关键 |
| 220 mm | 11/15（边距 10%）→ 15/15（边距 5%）| |
| 240 mm 及以上 | 15/15 | 与边距无关 |

这组数据是当前 `sampling.image_margin_fraction = [0.05, 0.05]` 的来源：5% 是按几何可行性下调的实测值，**不是误差预算结论**。同时收缩 `tray_corners_B` 对 FOV 判据没有影响（几何检查只校验 Food ROI 顶点），缩小 Food ROI 才会放宽下限。

当前 630 Pro 配置取 200 mm 单层 + Δ=0.02 m，实际光心 Z 覆盖 0.200–0.240 m，8 个视点全部采到，深度未触及 70–500 mm 量程边界（最深 0.236 m，ROI 最远约 318 mm）。

## 回放实现修正

原先 `replay` 在每个视点的动画开始前，直接在可见机器人上调用 `path_free` 做碰撞复核。复核需要逐点设置关节状态，因此会先把可见机器人瞬移到该视点轨迹的终点（每视点 12–188 次瞬移，耗时 46–731 ms），随后动画又从轨迹起点重新播放，视觉上表现为"跳到终点 → 停住 → 跳回起点"的割裂。

现在复核放在独立的 `DIRECT` 客户端（`gui=False`）上，可见机器人只由动画驱动。同时把回放改为按真实时钟推进的关节空间恒速播放（1.2 rad/s），每个采集位姿停顿 0.5 s 并绘制视锥。

实测（种子 `20261106`，当时的 12 视点运行）：

- 可见机器人的关节更新共 1194 次，相邻更新最大关节变化 0.0250 rad，等于插值步长，没有超过步长的跳变。
- 1097 次复核用的关节状态全部落在影子客户端上，可见客户端一次都没有被复核推动。
- GIF 共 450 帧、总时长 27.90 s，其中 12 个 500 ms 的停顿帧；相邻帧像素差中位数 0.72、p99 4.07、最大 4.83，没有脱离分布的单帧跳变。

## 输出裁剪开关

`quality.crop` 控制是否额外输出联合裁剪图：

```json
"quality": { "crop": { "enabled": false, "padding_px": 10 } }
```

- `enabled=false`（默认）：只输出全幅 `rgb.png` / `depth_mm.png` / `instance.png` / `food_mask.png`，尺寸恒为 640×360；报告页不显示「裁剪」标签页，metadata 不含 `crop_bbox_*`。
- `enabled=true`：在上述基础上额外输出 `crop_*`（外接框 = Food+Tray 投影并集 + 内边距，逐视点尺寸不同），metadata 增加 `crop_bbox_xyxy` / `crop_bbox_xywh` / `K_crop` / `tray_ratio_cropped`。
- 两种模式都记录 `image_size_xy` 与 `roi_bbox_xyxy`（仅记录投影框，不裁剪）。
- 兼容旧配置：缺 `quality.crop` 时按关闭处理，`quality.crop_padding_px` 仍作为内边距兜底值。

两种模式都已实跑并通过 `verify_results.py`；单元测试覆盖默认值、旧配置兜底、非法内边距、以及两种模式的导出文件集合。

## GUI 视角操作实测

PyBullet 3.2.7 的 GUI 只在按住修饰键时移动相机。用 XTEST 在真实窗口上逐项注入鼠标事件、读取 `getDebugVisualizerCamera` 的 yaw/pitch/dist/target 变化，结果如下（拖动 90×40 像素）：

| 手势 | 结果 |
|---|---|
| 左键拖动（无修饰键）| 无变化（不旋转，也不拖动场景物体）|
| `Ctrl`+左键、`Alt`+左键 | yaw −36°，pitch −16° |
| 中键拖动（无修饰键）| 无变化 |
| `Ctrl`+中键、`Alt`+中键 | 观察点平移 0.394 m |
| 右键（无修饰键）、`Alt`+右键 | 无变化 |
| `Ctrl`+右键 | 相机距离变化（被钳制到 ≥ 1.0 m）|
| 滚轮向下 5 格 | 距离 +1.28 m；滚轮向上无变化（已在下限）|

另在动画播放过程中注入手势：旋转、平移、缩放均生效，动画不中断；`resetDebugVisualizerCamera` 全程只被调用 1 次（`World` 初始化时），说明 `replay` 不会覆盖用户调整后的视角。

因为 `COV_ENABLE_GUI=0` 隐藏了 PyBullet 自带的提示面板，GUI 启动时会打印一行操作说明。
