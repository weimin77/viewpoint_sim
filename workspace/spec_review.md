# 规格评审：《视点规划技术调研 V1.1》

对 `视点规划技术调研V1.1.pdf`（23 页，内部技术评审）的技术评审记录。

- 评审对象：`视点规划技术调研V1.1.pdf`（不在仓库内）
- 页码指 **PDF 页码**，章节号与文档目录一致
- 数值验证基于本仓库 `outputs/demo` 的实测结果与默认配置
- 相关：实现侧追溯见 `workspace/spec_traceability.md`

## 总体评价

文档整体质量高，以下几处做得比同类调研扎实：

- 变换链约定（`T_A,B` 把 B 系点转为 A 系）全文自洽，`T_B,C = T_B,F·T_F,C` 与 `T*_B,F = T*_B,C·T_F,C⁻¹` 的推导正确，且明确警告"不能只转换 XYZ""不能把法兰目标当 TCP 目标"。
- §7.1 关于"凸包围盒在相机前方时，验 8 顶点即可判定包含关系"的论证正确，且指出了畸变/广角模型下的例外。
- §7.5 的 `r_tray ∝ 1/h²` 推导成立，是全文最有价值的一条定量关系。
- 反复强调"裁剪不能补救未入镜或超量程""终点可达不等于轨迹安全""不放宽硬约束强行接受"——抓住了这类系统的典型失效模式。

以下问题按严重度分级：A 级为实质性错误或逻辑缺陷，B 级为必然导致实现分叉的规格空白，C 级为方法论补强，D 级为硬件事实与引用，E 级为编辑问题。

## A 级：实质性错误或逻辑缺陷

### A1. §8.2 / §11.1 的公式与 §1.2 第 5 条自相矛盾

- §1.2(5)（p5）明确写："默认机器人 Base Z 轴近似竖直；**若不是，应改用工位定义的真实竖直单位向量**"。
- 但 §8.2（p16）的平移写成 `T'_{B,C} = [R_{B,C}, t_{B,C} + (0,0,Δh)ᵀ; 0 1]`，§11.1（p20）写成 `Z_C = z_tray + h + δ`。

两者都是 **Base Z 分量**。一旦 Base Z 不竖直，这两个公式直接失效，而前文刚提醒过这种情形。

**建议修法**：引入竖直单位向量 `g`，统一改写。

```
P_tray_ref = 相机光心在托盘参考面上的垂足
P_cam      = P_tray_ref + (h + δ)·g

方式 A: T'_{B,C} = [ R_{B,C} , t_{B,C} + Δh·g ; 0 1 ]
```

声明 `g` 默认为 `(0,0,1)`，非竖直工位必须显式配置。§7.5 的视场推导同样以"正俯视"为前提，需注明该前提。

### A2. §12.2「几何入镜率」定义自指，恒等于 100%

原文（p21）："**几何入镜率：经过筛选的**候选位姿中，3D ROI 是否全部落在设定的图像安全边界以内"。

被筛选通过的位姿**必然**已通过该检查（§7.7 采集前把它列为"必须满足"）。因此该指标恒为 100%，度量不到任何信息。同表的「实拍完整率」才是有意义的对照量。

**建议修法**：拆成两个分母不同的指标。

| 指标 | 分母 | 用途 |
|---|---|---|
| 几何通过率 | 全部候选（含被拒） | 诊断采样体积/高度是否合理 |
| 实拍入镜率 | 实际拍摄数 | 验证标定误差 |

### A3. §7.4 的 `r_min(h)` 缺可操作定义，这正是 §13 那条风险的根源

§13（p22）列出风险"多高度统一占比阈值不可行"，但 §7.4（p13）只说"`r_min(h)` 可以随拍摄高度不同而变化"——**没说朝哪个方向变、怎么定**。这不是接受无解，而是缺一步归一化。

理论占比上限：

```
r_max(h) = min(1, A_x·A_y / (W_fov(h)·H_fov(h)))
W_fov(h) = 2h·tan(HFOV/2),  H_fov(h) = 2h·tan(VFOV/2)
```

以 200×150 mm 托盘、D405 的 87°×58° FOV 计算，并对照本仓库 `outputs/demo` 的实测：

| 高度 | 理论上限 `r_max` | 实测原始占比 | 归一化效率 `r̃` |
|---:|---:|---:|---:|
| 200 mm | 35.6% | 29.6–34.5% | **83.0–96.7%** |
| 240 mm | 24.8% | 22.8–24.4% | **92.2–98.7%** |
| 280 mm | 18.2% | 17.6–18.1% | **96.6–99.5%** |

原始占比跨高度相差近 **2 倍**，任何固定阈值必然"整层全过"或"整层全拒"——这就是"统一阈值不可行"的数学根源。

**建议修法**（本文档最值得补的一条）：把指标归一化。

```
r̃_tray = r_tray / r_max(h)，  按 r̃_tray ≥ r_min（常数）判定
```

归一化后跨高度落在 83–99.5%，**单一常数阈值（如 0.80）即可通用**。这把"随高度调参"的问题降维成一个常数，同时让 §13 那条风险从"接受无解"变为"已解决"。

## B 级：规格空白（必然导致实现分叉）

| # | 位置 | 问题 | 建议 |
|---|---|---|---|

## C 级：方法论补强

### C1. §6.4 的筛选顺序把最贵的步骤放在最前

现行顺序（p10–11）：几何 → **IK → 碰撞 → 路径** → 多样性去重。

去重只需一次点积（微秒级），路径规划是 RRT（毫秒至秒级）。本仓库实测：280 mm 层 17 次尝试中 **9 次因 `duplicate_axis` 被拒**——若按文档顺序先做 RRT，这 9 次全部白算。

**建议**：几何 → 目标轴去重（便宜）→ IK → 碰撞 → 路径 → **到位后用实际位姿复验去重**。这是"更严不更松"的次序调整，不会误收候选。

### C2. §6.3 未指出：同一高度内"光轴夹角去重"≈"XY 间距去重"

固定高度 + 固定 look-at 目标时，`d` 是光心坐标的单调函数，因此夹角去重与 XY 欧氏距离去重**单调等价**。

**含义**：同一高度内，去重**无法提供超出 XY 采样所能给出的方位多样性**；只有跨高度它才捕捉到俯仰差异。这恰好解释了为什么 §12.2 必须额外要求"方位/倾角分布统计"——去重本身不保证覆盖均匀。建议将这段写入 §6.3。

### C3. §11 把"最大倾角"列为独立几何约束，但它其实是导出量

固定 look-at 目标时，`θ_tilt = atan(水平偏移 / 竖直间距)`。以典型工位（ROI 中心高 50 mm、XY 偏移上限 99 mm）计算：

| 高度 | 可达倾角上限 |
|---:|---:|
| 200 mm | 30.2° |
| 240 mm | 25.2° |
| 280 mm | 21.6° |

即 `max_tilt = 40°` **永不生效**；若把它设得比可达上限还小，会"整层静默全拒"且难以归因。

**建议**：标为**诊断/一致性检查项**并给出该关系式，或反过来用它反推可用 XY 范围。

### C4. §6.3 缺 N 与 θ_min 的可行性量级界

球面填充上界：`N_max ≤ 2 / (1 − cos(θ_min/2))`

| θ_min | N 上界 |
|---:|---:|
| 3° | ≈ 5836 |
| 6° | ≈ 1459 |
| 10° | ≈ 526 |
| 15° | ≈ 234 |

**含义**：对 N = 4~12 这个量级，夹角约束几乎不构成瓶颈——真正的瓶颈是入镜与 IK。附上此界可避免实现者把"调大 θ_min"误判为主要失败原因。

### C5. §9.3 未警示"离散插值检查会隧穿"

文档要求"运动路径必须单独验证"（p18），但未说明**离散采样不构成连续碰撞证明**。这是真机最典型的安全漏洞。

**建议**给出定量约束：`步长 × 连杆包络半径 < 最小障碍厚度 / 2`，或明确要求连续碰撞检测（CCD）。

### C6. §5.2 列了 4 项误差指标但没有判定规则

§5.2（p8）要求记录投影中心偏差、最大边界误差、误差稳定性、边距覆盖性，但**未给接受判据**，因此"记录四项指标"无法收敛为结论。

**建议补一句**：`max 边界误差 < M/2`（M 为安全边距）则接受当前外参，否则重新测量或转正式手眼标定。

### C7. §7.2 边距用百分比，而要覆盖的误差是像素量

10% 在 640×360 上是 64×36 px，在 1280×720 上是 128×72 px——**标定误差不随分辨率缩放**。

**建议**：写成"10% **或 ≥ X px，取较大者**"，并明确 `M > 标定误差 + 重复定位误差 + 目标定位误差`（三者都用像素表达）。

## D 级：硬件事实与引用准确性

### D1. D405 的 RGB 不是独立传感器

D405 的 RGB 由左目深度成像器经 ISP 生成，与 Depth **共享 87°×58° FOV 且硬件配准**。因此：

- §7.1（p11）"进一步检查 RGB 与 Depth 的**共同可用视野**"——对 D405 是**空检查**
- §7.6（p14）"RGB 与深度**视场差异**"——对 D405 **不成立**

**建议**：在 §7.1 加设备特定说明——D405 下 `T_CD = I`、内外参同源，该项可跳过。**必须点明前提**：若换用 D435i（独立彩色传感器、FOV 更窄），这项检查就变成必需，且 `T_CD` 不再为单位阵。

### D2. "标称工作范围 7–50 cm"的措辞偏硬

Intel 对该区间的表述是 **"ideal range"（理想范围）**：7 cm 是较硬的 min-z，50 cm 是理想区间上端，**超出后精度下降但并非无效**。

**建议**改为："7 cm 以下不可用；7–50 cm 为理想范围；>50 cm 精度下降，按实测有效率决定"。若实现把 50 cm 当硬上限直接判废（如 `depth_range = [0.07, 0.5]`），会在高位过度拒绝。

## E 级：编辑与可读性

### E1（重点）字体 ToUnicode 损坏，全文公式不可复制、不可检索

实测：23 页中 **18 页**含数学字体（`LatinModernMath-Regular`），**753 处、78 个码位**映射到错误的 Unicode 区块：

| 应显示 | 实际提取 | 提取到的码位 | 出现次数 |
|---|---|---|---|
| θ（最小夹角） | `ᅲ` | U+1172 韩文中声 YU | 3 |
| Δ（扰动幅度） | `ᅮ` | U+116E 韩文中声 U | 25 |
| δ（单次扰动） | `ᆃ` | U+1183 韩文中声 O-U | 11 |
| 下标 B | `գ` | U+0563 亚美尼亚字母 GIM | 43 |
| 下标 C | `դ` | U+0564 亚美尼亚字母 DA | 47 |
| 下标 F | `է` | U+0567 亚美尼亚字母 EH | 25 |
| `T`（矩阵） | `𝑇` | U+1D447（此项为正确映射） | 37 |

影响：无法把公式复制进代码或配置；无法全文检索（`grep 'θ'` 命中 0）；任何自动化/OCR/AI 摄取都会读到乱码。

**验证方法**：

```bash
pdftotext 视点规划技术调研V1.1.pdf - | grep -c 'θ'   # 期望 > 0，当前为 0
```

**修法**：用正常数学排版流程重新导出。Word 公式建议先转 OMML；LaTeX 侧确认未禁用 ToUnicode 映射。

### E2. `ROI` 一词双义

"Food ROI"（三维包围盒）与"Tray ROI"（平面四边形）在 §7.4 起混排，§12.2 的"3D ROI"与"Tray ROI"并列尤其容易误读。建议全文只用全称。

### E3. §14 阶段1 的"用少量已知拍照位姿"不可实现

`T_F,C` 未定时无法"已知相机位姿"；可已知的是**关节角**。

**建议**改为："已知关节角（经 FK 得法兰位姿，再用待验证的 `T_F,C` 预测相机位姿）"。

### E4. 单位混用

§4.1（p7）用 mm，§7.3（p12）用 cm，§11（p20）建议"统一坐标单位"却未指定基准。

**建议**全文统一 m / rad（与 `T_A,B` 的齐次坐标约定一致），示例保留 mm 但显式标注单位。

## 附一：数值复算

本文 A3、C3、C4 的数值可用下列脚本复现（不依赖仓库代码，仅用标准库）：

```python
import math

# A3 / §7.4: 理论占比上限与归一化效率
Ax, Ay = 0.200, 0.150              # 托盘 200 x 150 mm
hfov, vfov = 87.0, 58.0            # D405 FOV
for h in (0.20, 0.24, 0.28):
    W = 2*h*math.tan(math.radians(hfov/2))
    H = 2*h*math.tan(math.radians(vfov/2))
    print(f"h={h*1000:.0f}mm  r_max={min(1,(Ax*Ay)/(W*H)):.3f}")

# C3: 固定 look-at 目标时倾角是导出量
z_center = 0.050                   # ROI 中心高
off = math.hypot(0.070, 0.070)     # XY 偏移上限
for h in (0.20, 0.24, 0.28):
    print(f"h={h*1000:.0f}mm  tilt_max={math.degrees(math.atan(off/((0.020+h)-z_center))):.1f}deg")

# C4: 球面填充上界
for th in (6, 10, 15):
    print(f"theta_min={th}deg  N_max<={2/(1-math.cos(math.radians(th/2))):.0f}")
```

实测占比取自 `outputs/demo/views.json` 的 `geometry.tray_ratio_raw`，理论上限按上式独立计算。
