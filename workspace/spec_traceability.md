### 1.3 总体方案与功能分层（§2，p4–5）

规格推荐拆三个模块：

| 规格模块 | 规格输入 | 规格输出 | 仓库对应 | 状态 |
|---|---|---|---|---|
| ROI & Height Configuration | 示教点、最大食材高度、基准高度与扰动幅度 | 空间约束参数、场景描述、固定平面与可选 Z 扰动 | `config.py` + `configs/default.json` | 🟡 见 **P2-b**（示教链缺失） |
| Random Viewpoint Planner | ROI、高度与扰动范围、相机内外参、机器人模型 | 约束筛选后的有效视点 | `planner.py` `geometry_check()` 部分 | 🟡 见下 |
| Robot Motion Executor | 相机位姿、安装外参、机器人模型 | 机械臂动作与采集结果 | `kinematics.py`/`motion.py`/`world.py`/`acquisition.py` | ✅ |

**偏差**：规格把"视点生成"与"机器人验证"彻底分开，仓库把它们交织在 `planner.run()` 的单层循环里（IK、碰撞、路径、采集在同一个 `while` 内）。

后果：**无法脱离机械臂单独评估几何筛选通过率**，而这正是 §12.1「随机采样有效率」要统计的指标。要做 P1-b 分布统计或 §12.1 验收指标时，这个耦合会成为障碍。

## 3. 架构层观察（非分级项）

规格 §2（p4–5）推荐三模块分层，仓库实际 10 模块：

```
config → geometry → kinematics → world → motion → acquisition → planner → comparison → report → cli
```

**边界差异**：规格把"机器人验证"与"视点生成"彻底分离，仓库在 `planner.run()` 的单个 `while` 循环里交织了采样、几何、IK、碰撞、路径、采集。

**实际影响**：无法脱离机械臂单独评估几何筛选通过率——而这是 §12.1（p21）「随机采样有效率」要统计的指标。做 P1-b 或 §12.1 全套验收指标时，此耦合会成为障碍。

**说明**：这是设计取舍，不违反任何规格条款（规格用"推荐"表述）。仅记录其与 P1-b / §12.1 的相互作用。
